# CDC 診断ログの変化検出ロジック（v2.7）

[English](CDC_CHANGE_DETECTION_EN.md) | [日本語](CDC_CHANGE_DETECTION.md)

## 概要

v2.7から、CDC診断ログに**変化検出ロジック**を導入しました。無変化時の出力を削減することで、ログサイズを約 **98.8～99.0% 削減**しながら、必要な診断情報は十分に保持しています。

実機テスト結果（Windows 11 26H2 UAC2モード、15.8分間）:
- **削減率: 98.8%**（48.5 MB → 0.59 MB）
- **行数: 99.0% 削減**（569,257 行 → 5,896 行）

## 出力判定ロジック

### 周期ログ（Periodic Sampling）

**出力周期**: 100ms（判定）+ 1秒ごとの強制出力

100ms周期で以下の条件のいずれかを満たすときのみ周期ログを記録します。

```c
bool should_write_sample(void) {
    return (abs(HOST_RATE - prev_host_rate) >= 50) ||      // ホストレート変化
           (abs(FEEDBACK_RATE - prev_feedback_rate) >= 50) || // フィードバックレート変化
           (abs(RING_NOW - prev_ring_now) >= 200) ||         // リングレベル変化
           (UNDERFLOW_COUNT != prev_underflow_count) ||      // アンダーフロー増加
           (USB_STATE != prev_usb_state);                    // USB状態遷移
}
```

加えて、**1秒ごとに強制出力**して、最低限の可視性を確保します。

**関連定数:**
- `CDC_LOG_FORCE_PERIOD_US`: 1,000,000 µs（1秒）
- `CDC_SAMPLE_INTERVAL_US`: 100,000 µs（100ms）

**フィールド値の範囲:**
- `HOST_RATE`: USB OUT受信時の推定ホストサンプルレート（Hz、単位: Hz）
  - 典型値: 44,100 ～ 192,000 Hz
- `FEEDBACK_RATE`: 計算されたフィードバックレート（Hz）
- `RING_NOW`: 音声リングバッファーの現在フレーム数（フレーム）
  - 容量: 4,096 ステレオフレーム（全体）
  - 標準フィードバック目標: 2,048 フレーム（50%）
- `UNDERFLOW_COUNT`: 起動後のアンダーフロー累積数（増加したときのみ記録）

### FAST ログ（Fast Sampling）

**出力周期**: 1ms（判定）+ 500ms ごとの強制出力

1ms 周期で以下の条件のいずれかを満たすときのみFASTログを記録します。

```c
bool should_write_fast_sample(void) {
    return (abs(RING_NOW - prev_ring_now) >= 200) || // リング変化検出
           (time_since_last_fast_output >= 500000);   // 500ms強制出力
}
```

**関連定数:**
- `CDC_FAST_FORCE_PERIOD_US`: 500,000 µs（500ms）
- `CDC_FAST_CHANGE_THRESHOLD_RING_FRAMES`: 200 フレーム
- `CDC_FAST_SAMPLE_INTERVAL_US`: 1,000 µs（1ms）

**出力間隔の実績（実機テスト）:**
- 平均間隔: 約 247.67 ms
- 範囲: 1 ms ～ 500 ms 以上
- 中央値: 約 63 ms（リング変化検出が主原因）
- 行数比率:
  - 強制出力（≥500ms の差分）: 約 47%（1,807 行）
  - リング変化検出（<500ms の差分）: 約 53%（2,028 行）

**フィールド値:**
- `RING`: 音声リングバッファーの現在フレーム数（フレーム）
- `FB_LEVEL_X10`: フィードバック目標水位×10（例: 20480 = 2048.0 フレーム）

## ホストレートと周期ログの判定

### HOST_RATE の推定方法

`HOST_RATE` はUSB OUT受信パケット到着時刻から、250ms窓での推定値として計算されます。

- **計算単位**: Hz（サンプリングレート）
- **計算窓**: 250ms
- **推定対象**: 最後の250ms 間に受信したサンプルフレーム数

したがって、公称レート内での推定値の揺らぎや、レート切替をまたぐ窓での大きな差は、ホストの異常ではなく推定の性質です。

### 周期ログの判定精度

判定閾値50Hz は以下の前提で設定されています：

- **目的**: 意図的なレート切替や、実質的な帯域幅変化を記録
- **同一レート内の揺らぎ**: 推定窓の特性により、±50Hz 程度の変動は検出しない
- **実装上の注意**: サンプルレート切替（例: 48 kHz → 96 kHz）は判定ロジック内の `FREQ` または `NOMINAL_RATE` フィールドの変化と連動して検出

周期ログ中の `RATE_CHANGE_COUNT` は、**CDCログセッション開始時点からの累積レート切替数**です。起動直後のカウンター値との差から、当該セッション中の実切替回数が特定できます。

## ストレージ効果と限界

### 削減効果

| 項目 | 実績 | 備考 |
|-----|------|------|
| ファイルサイズ | 48.5 MB → 0.59 MB | 98.8% 削減 |
| 行数 | 569,257 → 5,896 | 99.0% 削減 |
| 試験時間 | 15.8分（950.6秒）| Windows 11 26H2 UAC2 |
| FAST ログ | 3,836 行 | 平均 247.67 ms 間隔 |
| 周期ログ | 1,313 行 | 100ms 判定 + 1秒強制出力 |

### 注意事項

1. **診断ビルド（`USB_BRINGUP_LEVEL >= 3`）での長時間記録**
   - CDC診断版では起動直後に診断画面を表示し、音声再生（FFT処理）を停止します
   - 音声再生負荷がないため、通常ビルドと比べてリングレベルやホストレートの挙動が異なる可能性があります
   - ログ取得目的の場合は、長時間記録が実用的になりましたが、パフォーマンス評価はFFT有効ビルドで実施してください

2. **リング変化の原因特定**
   - FASTログのリング値変化は、以下を含みます:
     - 正常な再生バッファー消費・補充
     - サンプルレート切替時の補正
     - 受信停止・復帰時の変動
   - **アンダーフロー判定**: `UNDERFLOW_COUNT` の増加で確認（ログ内に `UNDERFLOW` 行で出現）
   - 単一のリング値変化だけでは原因が特定できません

3. **出力間隔の推定**
   - FASTログの出力理由（強制出力 vs リング変化）を詳細に分析する場合は、時刻差（`UNIX_US` または `UPTIME_US`）から推定する必要があります
   - 出力理由を明示する専用列は、現在のCSV形式には含まれていません

## ホストレート切替の検出

周期ログ中の `RATE_CHANGE_COUNT` を参照することで、当該セッション中のレート切替回数が確認できます。

```
初期値（セッション開始時）: rate_change_initial
現在値（セッション中）: rate_change_count
当セッション中の切替回数 = rate_change_count - rate_change_initial
```

**実機テスト結果（15.8分）:**
- セッション中の公称レート切替数: 15 回
- 判定対象外の揺らぎ: 多数（50Hz未満の変動）

## 今後の最適化案

| 案 | 実装難度 | 期待効果 | 説明 |
|-----|---------|---------|------|
| A | ⭐⭐ 中等度 | 周期ログ削減 | ホストレート判定閾値を50Hz→100Hz に変更（レート切替検出精度は低下） |
| B | ⭐ 簡単 | FAST削減 | FAST強制出力間隔を500ms→1,000ms に延長（FFT出力頻度は減少） |
| C | ⭐⭐⭐ 困難 | 高度な分析 | 動的閾値設定：同一レート中の推定値揺らぎから自動設定 |

**推奨**: 改善案 B の実装から開始（リスク低、実装簡単、効果大）
