## USBイベントログ

画面下部にUSB通信イベントを表示します。

- 3列 × 8行
- 最大64件（CDC有効時は256件）を保存
- 最新イベントは左上、最古イベントは右下

操作：

- Aボタン：古いイベント
- Bボタン：新しいイベント

表示時刻は起動後の経過秒数です。

このログはイベント発生時にだけ記録され、定期的な再生状態ログではありません。Yボタンを3秒長押しすると診断値とイベントログが消去され、以後のイベントから記録を再開します。

##### イベント記号

| 記号 | 意味 |
|------|------|
| M | USB Mount |
| J | USB初期化時の音声状態（初期IDLE） |
| P | CDC接続判定の変化（01：USBが構成済み・非サスペンドかつDTR有効、00：それ以外） |
| L | CDCライン状態要求（最初の値：DTR、次の値：RTS、CDC有効ビルドのみ） |
| Q | USBサスペンド（最初の値：リモートウェイクアップ許可、CDC有効ビルドのみ） |
| V | USBレジューム（CDC有効ビルドのみ） |
| A | HostからのAudio Streaming Interface Alt=0要求 |
| I | HostからのAudio Streaming Interface Alt>0要求 |
| O | `usb_audio_stream_open()` |
| C | `usb_audio_stream_close()`（構成記述子要求にも使用） |
| R | `usb_audio_apply_sample_rate()` |
| W | サンプルレート切替開始／`service_switch()`内の処理 |
| K | `service_switch()`完了 |
| G | USBコントロール要求 Get |
| S | USBコントロール要求 Set／オーディオ状態遷移 |
| U | USB切断 |
| D | デバイス記述子要求／バッファードレイン完了 |

イベント記号の一部は複数の用途で使われます。特に`C`、`S`、`D`は、後続の16進数フィールドとイベントの前後関係をあわせて判別してください。Alt切替時の`A → C → I → O`は、Alt=0要求、ストリーム終了、Alt>0要求、ストリーム開始の順を示す通常の動作であり、異常ではありません。

結果の接尾辞：

成功

```text
+
```

失敗

```text
-
```

## 表示仕様（Pico Display Pack 2.0）

起動時に起動画面を表示し、初期化が完了すると通常ビルドでは再生画面、CDC有効ビルド（`USB_BRINGUP_LEVEL=3`）では診断画面に切り替わります。CDC有効ビルドでは再生画面、FFT処理、FFT入力の収集を停止します。
起動完了時は下段の`System Ready`を約0.5秒後に消去し、上段の表示は残ります。

Pico Display Pack 2.0のXボタンで、以下の画面を一方向に切り替えられます。

- 起動画面
- 再生画面（CDC無効ビルドのみ）
- 診断画面
- フィードバック監視画面
- 再生開始ログ画面（CDC有効ビルドのみ）

ボタン操作：

- X：次の画面（CDC有効時は起動画面 → 診断画面 → フィードバック監視画面 → 再生開始ログ画面 → 起動画面。CDC無効時は起動画面 → 再生画面 → 診断画面 → フィードバック監視画面 → 起動画面）

診断画面では以下の操作ができます。

- A：古いUSBログへ移動
- B：新しいUSBログへ移動
- A+B：USBログと直近の音声状態履歴を切り替え
- Yを3秒長押し：診断カウンターとUSBイベントログをリセット（押している間、画面下にカウントダウンを表示）

USBイベントログは起動時から記録され、診断画面では直近64件（CDC有効時は256件）を確認できます。USBバスリセット/切断、デバイス・構成・文字列記述子要求、構成完了/解除、UAC制御要求など、イベント発生時に記録します。一定間隔で再生状態を記録するログではないため、再生中に新しいイベントがなければログ表示は変わりません。曲の切り替えなどでUSBオーディオの状態が変化すると、新しいログが追加されることがあります。Y長押しでリセットすると、それまでの診断値とUSBイベントログを消去し、その後に発生したイベントから記録を再開します。O/F/S/C/Uのイベントカウンターは画面にかかわらずイベント発生時に更新されます。一方、バッファー水位や処理間隔などの周期的な診断統計は診断画面、フィードバック監視画面、パケット記録画面を表示中、あるいはCDC接続中に収集されます。診断画面を離れても取得済みの診断値は保持され、再入場後はその値から計測を再開します。再生画面では再生、FFT、ビット深度・サンプルレート表示を継続します。

ログ履歴は電源断で消えるため、必要に応じてUSBを抜く前に撮影してください。

#### フィードバック監視画面

診断画面からXを押すと`FEEDBACK MONITOR`を表示します。表示は約0.5秒ごとに更新され、描画は音声バッファーに余裕があるときに少しずつ行います。

- `BUF`：現在のリング水位、`DEV`：現在水位から目標水位を引いた値。単位はステレオフレームです。
- `FB`：ホストに要求するフィードバック周波数の整数Hz表示。`OFF`：内部のFB周波数からI²S実効レートを引いた補正量（0.1 Hz単位）。PIの積分項だけでも、実測したクロック誤差でもありません。停止・切替中は`----`です。
- `1s`：この画面でストリーミング中にサンプリングした直近の完了した約1秒間の最小・最大リング水位、`PP`：その差。DMAの全ての瞬間的な極値を捕捉するとは限りません。入場直後や再生停止後は有効な1秒間が完了するまで`----`です。
- `UF`：リングとDMAプールの低水位によるアンダーフロー検出回数、`OF`：リング高水位または書き込み失敗によるオーバーフロー検出回数。診断画面のY長押しでリセットできます。これらがゼロでも全てのプツ音がないことを保証しません。

#### 再生開始ログ画面

CDC有効ビルド（`USB_BRINGUP_LEVEL=3`）では、フィードバック監視画面からXを押すと`PLAYBACK START LOG`画面を表示します。Android接続時もCOMポートを開かずに記録され、接続中に写真で確認できます。`SILENCE EVENTS`は無音補完の開始回数、`SILENCE FRAMES`はDMAに投入した無音フレームの累積です。投入後に停止した分も含むため、実際に再生されたフレーム数とは限りません。

履歴は新しい順に表示し、Aで古い記録へ、Bで新しい記録へ移動します。状態遷移行は起動後の秒（100000秒ごとに周回）・遷移前後の状態・サンプルレート・リング水位`R`・DMAプール水位`D`を示します。例えば`BUFF>STRM`は再生開始時の水位です。無音補完は`SILENCE START`、PCMへの復帰は`SILENCE PCM`、DMA停止は`SILENCE STOP`で、終了行の`F`はその期間に投入した無音フレーム数です。DMAプール水位は再生中ブロックを含む上限概算です。

画面の履歴はCDC送信とは独立して直近128件を保持し、上書き件数は`HISTORY OVERWRITTEN`に表示します。診断画面のY長押しでは消えませんが、電源断・再起動で履歴と累積値は消えるため、USBを抜く前に撮影してください。

### 再生画面

再生画面には、以下の情報がリアルタイム表示されます。

#### L/Rレベルメーター

左右の音声レベルをリアルタイムに表示します。

#### L/R独立11バンドFFT表示

A特性補正を適用した左右チャンネルの周波数スペクトルを個別に表示します。
FFTバーは左チャンネル、右チャンネルの順にチャンネルごとに分けて更新します。

#### オーディオ情報

現在のビット深度とサンプルレート（Fs）を表示します。

#### 表示に関する注意

※L/Rレベルメーターのピーク表示は入力信号レベルに合わせて連続的に更新されるため、ちらついて見えることがあります。これは正常な動作です。

音楽を再生していてもFFTバーやピークメーターが動かない場合は、まずスマートフォンやPCなどホスト側の音量設定を確認してください。本機のメーター表示はソフトウェアゲインに連動するため、ホスト側の音量が極端に小さい場合やミュートされている場合は、画面に反応が表示されないことがあります。

### 診断画面

Xボタンによる画面順は、CDC無効ビルドでは起動画面 → 再生画面 → 診断画面 → フィードバック監視画面、CDC有効ビルドでは起動画面 → 診断画面 → フィードバック監視画面 → 再生開始ログ画面です。パケット記録を有効にした診断ビルドでは、再生開始ログ画面の後にパケット記録画面が加わります。Yボタンは画面移動には使わず、診断画面で3秒長押しすると診断カウンターとUSBイベントログをリセットし、パケット記録が有効な場合は再武装します。操作と制約は[Android検証手順](ANDROID_TEST.md)を参照してください。

UAC表示の下にファームウェア版（例：`v2.5`）、その下に現在のシステムクロックを表示します。`D330`は330MHz（初期化時および44.1/88.2kHz）、`D307`は307.2MHz（176.4kHz）、`D360`は360MHz（48/96/192kHz系）です。USB音声データの受信が1秒間途絶え、出力のゼロ検出が完了するとI²Sクロックは停止します。この表示はシステムクロックを示すもので、I²Sクロックの動作状態は示しません。

#### オーディオ状態表示

画面上部に、現在のUSBオーディオとバッファーの状態を表示します。

##### STATE

| 状態 | 説明 |
|------|------|
| IDLE | 停止中 |
| BUFF | バッファリング中 |
| STRM | ストリーミング中 |
| SWCH | サンプルレート切替中 |
| OVF! | バッファーオーバーフロー |
| UDF! | バッファーアンダーフロー |

##### HOST / FB

- HOST：ホストが要求したサンプルレート
- FB：ホストへ通知しているフィードバック周波数

##### ビット深度 / サンプルレート

次の形式で表示します。

```text
24bit 96.0kHz
```

##### RING / LEVEL

リングバッファーの現在の充填量と、全容量に対する割合を表示します。白いマーカーは目標バッファーレベルを示します。

バッファ水位は完全に一定値へ固定されるわけではありません。

Windowsや再生ソフト、USB転送タイミングなどに起因するホスト側送出レートの微小な変動に対し、PI制御がUSB Feedbackを連続的に補正します。

そのため、目標水位付近では水位がわずかに上下しながら維持されるのが正常動作です。

##### 水位表示値

`@`は現在のリング水位、`n`/`x`は再生中に記録された最小/最大水位です。例えば`@0000`、`n2049`、`x3072`のように表示します。単位はサンプルフレームです。値の先頭記号で区別するため、MIN/MAXの文字見出しは表示しません。

#### 診断カウンター

診断画面の右側に処理統計を表示します。

| カウンター | 説明 |
|------------|------|
| O | リングバッファーオーバーフローにより破棄されたフレーム数 |
| F | USB受信FIFO高水位時に破棄された古いフレーム数 |
| S | サンプルレート切替中に破棄されたフレーム数 |
| C | 再起動または停止処理中にクリアされたフレーム数 |
| U | 再生中に検出された出力停止回数 |
| a | Core0の最大処理間隔（µs） |
| b | Core1の最大処理間隔（µs） |
| T | DMA末尾ブロックの出力回数 |
| B | USB受信中にBUFFERINGが1秒以上続いた回数 |
| K | レート切替中またはBUFFERING中にクロック再開が250ms以上続いた回数 |
| V | オーバーフロー検出回数 |
| R | STREAMINGまたは障害状態からBUFFERINGに戻った回数 |

O/F/S/C/U/B/K/V/Rは画面にかかわらずイベント発生時に加算され、リセット後の累積値を示します。B/KはCDC未接続時にも表示され、0以外は赤色です。現在の待機がタイムアウトし、出力停止かつDMAが無音の場合に限り、低水位でもログ見出しの位置に`Bxxxx Kxxxx 状態 BK`を1秒に1文字ずつ描画します。末尾の`B`／`K`は現在滞留している待機の種類を示し、該当しなければ`-`です。待機が終わると低水位での特別描画を停止し、通常の描画条件を満たした後に見出しを戻します。待機タイムアウトは診断のみで、強制停止や自動復旧は行いません。TはDMA末尾ブロックの出力条件を数えますが、診断統計が有効で、かつストリーミング中に限り加算されます。a/bやバッファー水位などの周期的な測定値も、診断画面・フィードバック監視画面・パケット記録画面の表示中またはCDC接続中に収集された値です。

O/F/S/C/U/B/K/V/Rの画面表示は4桁で、9999を超える値も9999と表示します。

現在の滞留判定は累積カウントと独立しています。BUFFERINGはUSB受信が継続している間だけ計測し、受信が途切れた後の再開時には計測をやり直します。クロックはBUFFERINGまたはSWITCHING中の再開処理を開始時刻から計測し、通常のアイドル停止中は滞留としません。起動時無音中は判定せず、その間に始まったBUFFERINGは無音期間の終了時以降に計測します。

安定動作時には、通常、以下の値が期待されます。

```text
O = 0
F = 0
U = 0
```

#### 再生停止時に記録する情報

再生停止や音切れが発生した場合は、可能であればすぐに診断画面を撮影してください。USBイベントログには直近の64件（CDC有効時は256件）が保存されます。

以下の情報を記録してください。

- STATE
- HOST
- FB
- RING / LEVEL
- 水位の現在値・最小値・最大値
- O / F / S / C / Uカウンター
- a / b / Tカウンター
- USBイベントログ全体
- 発生時のサンプルレートとビット深度
- PCのOS
- 再生ソフトウェア
- 発生時刻
- 発生直前に行った操作
- 自動的に再生が再開したか
- USBの再接続が必要だったか

これらの記録はUSB通信状態、バッファー動作、音声出力の状態を関連づけ、トラブルシューティングに役立ちます。故障分析の相談にAIサービスを利用する場合にも活用できます。

※シリアル番号などの個人情報は共有しないでください。

再生画面には診断情報は重ねて表示されません。



## 音声異常コードと状態履歴

音声状態履歴は通常再生中も約100ms間隔で記録されます。異常を検知すると、その直前約4.8秒と直後約1.6秒の履歴を固定して診断画面で確認できます。異常イベントはUSBログへ赤色の`E`項目として追加されます。コードは`01`バッファーアンダーフロー、`02`オーバーフロー/破棄、`03`USB受信FIFO高水位時の古いデータ破棄、`04`USBバスリセット/切断、`05`再生出力停止、`06`Core0処理間隔超過、`07`Core1処理間隔超過、`08`USB OUT受信間隔3ms以上、`09`PIO TX FIFO stall、`0A`DMA AHB転送エラー、`0B`PCM形式、`0C`PCMフレーム境界、`0D`クリック候補です。クリック候補は正常な音声でも記録される可能性があります。これらのイベントはCDCログにも発生時点の状態・レート・リング水位・DMA水位を記録します。PIO stallは出力開始後10msを過ぎてから監視します。履歴表示の各項目は「秒・状態・リング水位・DMA水位」を表します。

`0A`検出時はDMAを停止・クリアし、再生中なら再バッファリングします。詳細値のビット0はREAD、ビット1はWRITEエラーです。`DROP_FRAMES_UPPER`は復旧時に破棄するDMAプールのフレーム数の上限で、再生済みの一部も含み得ます。クリア破棄数にもこの上限を加算します。異常ログは間引かれるため、連続発生の全件が記録されるとは限りません。復旧動作は実機での確認が必要です。
