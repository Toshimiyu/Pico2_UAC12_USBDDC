================================================================================
Pico2 UAC12 USB DDC v2.7
================================================================================

Raspberry Pi Pico 2（RP2350）向けUSB-DDCファームウェアのバージョン2.7です。

UAC1／UAC2の切り替え、非同期フィードバック制御、バッファー監視、診断ログに対応しています。
通常版のファームウェア名は「v2.7」、CDC診断版は「v2.7T」です。


【v2.7の主な変更点】

■ CDC診断ログの変化検出ロジック実装

・無変化時の出力を削減し、ログサイズを約98.8～99.0%削減しました。
  実機テスト（15.8分間）：48.5 MB → 0.59 MB

・周期ログ（100ms周期）の出力判定：
  以下の条件のいずれかを満たすときのみ記録
  - ホストレート（HOST_RATE）が前回比 50Hz 以上変化
  - フィードバックレート（FEEDBACK_RATE）が前回比 50Hz 以上変化
  - リングレベル（RING_NOW）が前回比 200フレーム 以上変化
  - アンダーフロー（UNDERFLOW_COUNT）が増加
  - USB状態が遷移
  加えて、1秒ごとに強制出力して最低限の可視性を確保

・FASTログ（1ms周期）の出力判定：
  以下の条件のいずれかを満たすときのみ記録
  - リングレベル（RING_NOW）が前回比 200フレーム以上変化
  - 500ms ごとの強制出力

・実装詳細は docs/CDC_CHANGE_DETECTION.md を参照してください。
・実機テスト結果は LOG_ANALYSIS_REPORT_v2_CORRECTED.md を参照してください。

■ Windows 11 26H2 での実機テスト確認

✓ v2.7以降、Windows 11 26H2 環境でのUAC2モード動作時にノイズは確認できていません。
✓ 長時間（15.8分間）のログ取得時にも、ログサイズ削減（98.8%）と診断情報の保持が
  両立していることを確認しました。
✓ 複数のサンプリングレート（44.1kHz、48kHz、88.2kHz、96kHz、176.4kHz、192kHz）で
  切り替えテストを実施し、15回のレート切替イベントを検出・記録しました。

【v2.6 から継続する機能】

・ビルド・自動化インフラの改善（Level 2～4の複数レベルビルド対応）
・メモリ最適化（イベントログバッファサイズの条件付き削減）
・UAC1／UAC2の切り替え、非同期フィードバック制御、バッファー水位監視
・PCMサンプル幅とステレオフレーム境界を検証し、不正データ検出時にUSB受信FIFOを再同期
・入力PCMの急峻な変化をPCM_CLICK_CANDIDATEとして記録
  ※正常な信号でも候補として記録される場合があります
・USBミュート／解除時に約5msのゲインランプを適用
・再生中のストリーム終了要求後、残りのPCMに約20msのフェードアウトを適用
・PCM不足時のフェードアウト：サンプルレートに応じた約5ms
・ホストがゼロPCM送信時：2ms以上の無音後に約5msでフェードイン
・起動時I²Sゼロ出力：7秒間（この間のUSB音声データは破棄）
・通常ビルドで11バンドFFT表示
・バッファー水位モニター、USB診断画面、イベントログ
・ソフトウェアによるオーバーサンプリング、FIRフィルター、サンプルレート変換なし

音声出力には固定ゲイン比0.80と、UACの音量・ミュート設定が適用されます。

・32-bit PCM：44.1、48、88.2、96kHz


【確認状況】

・v2.7 のCDC変化検出ロジック実装はコード・ドキュメント両面で完了しました。
・Windows 11 26H2 環境でのUAC2モード長時間テストを実施し、
  ノイズなし・ログ削減・診断情報保持の3点を同時に確認しました。
・複数のサンプリングレート（44.1kHz～192kHz）での動作を検証しました。
・v2.6 のビルドインフラ（Level 2～4）はすべて引き継ぎます。
・実機でのビルドとファームウェアの機能動作は v2.6 を継承しています。
・ビルド環境はRaspberry Pi Pico SDK v2.3.1、Toolchain 15_2_Rel1です。
・ビルドにはリポジトリ同梱のTinyUSBを使用してください。


【ビルド出力】

UAC1：Pico2_UAC12_USBDDC_UAC1.uf2
UAC2：Pico2_UAC12_USBDDC_UAC2.uf2


【VS Code でのビルド方法】

・configure-vsc-build.ps1 スクリプトを実行してください。
・以下のコマンドで簡潔にビルドできます：
  cmake -S . -B build -DUSB_AUDIO_CLASS_VERSION=2
  cmake --build build


【CDC診断ログの実装詳細】

変化検出の閾値：
・ホストレート（HOST_RATE）：50Hz 以上の変化で記録
・フィードバックレート（FEEDBACK_RATE）：50Hz 以上の変化で記録
・リングレベル（RING_NOW）：200フレーム 以上の変化で記録
・FASTログのリング変化検出：200フレーム 以上で記録、500ms ごと強制出力

実装された関数と定数：
・should_write_fast_sample()：FASTログの出力判定関数
・CDC_LOG_FORCE_PERIOD_US：周期ログ強制出力間隔（1000000µs = 1秒）
・CDC_FAST_FORCE_PERIOD_US：FASTログ強制出力間隔（500000µs = 500ms）
・CDC_LOG_CHANGE_THRESHOLD_HOST_HZ：ホストレート変化検出閾値（50Hz）
・CDC_LOG_CHANGE_THRESHOLD_FB_HZ：フィードバックレート変化検出閾値（50Hz）
・CDC_FAST_CHANGE_THRESHOLD_RING_FRAMES：リング変化検出閾値（200フレーム）

詳細な実装内容は src/cdc_diagnostics.c を参照してください。


【実機テスト結果】

テスト環境：
・ホストOS：Windows 11 26H2
・USBクラス：UAC2
・テスト期間：15.8分（950.6秒）
・複数周波数試験：44.1kHz、48kHz、88.2kHz、96kHz、176.4kHz、192kHz

削減効果：
・ログサイズ：48.5 MB → 0.59 MB（削減率 98.8%）
・行数：569,257 → 5,896（削減率 99.0%）
・FAST出力行数：3,836（平均間隔 247.67ms、中央値 63ms）
・周期出力行数：1,313
・STATE出力行数：97

検出内容：
・ホストレート切替イベント：15回を確実に検出・記録
・リング値の最大変化：2,203フレーム（観測値）
・複数周波数での動作確認：6周波数すべてで検証
・ノイズ確認：なし（UAC2モード）

分析詳細は LOG_ANALYSIS_REPORT_v2_CORRECTED.md を参照してください。


【注意事項】

・v2.7 のファームウェアコア機能は v2.6 と同じです。
  主な変更はCDC診断ログの変化検出ロジック実装です。
・AndroidではUAC1モードを使用してください。
・UAC2のFull-Speedフィードバックは現在4バイトで送信されます。
  ホスト互換性は別途実機確認が必要です。
・UAC2のCLK_VALIDはレート切替中も1を返します。
  この動作のホスト互換性は未検証です。
・USBリセット単独によるOFFSET_SEED無効化と、60分経過後の失効は実機未確認です。
・現在のUSB識別子0x2e8a:0xfedeのPID割り当ては未確認です。
  配布前に割り当てを確認してください。
・RP2350はUSB Full-Speedデバイスとして動作します。
  UAC2の24／32-bit PCMは最大96kHzです。
・CDCログの読み取りが長時間停滞するとログ行が欠落する場合があります。
・再生安定性はホスト設定、再生ソフト、ドライバー、システム負荷に依存します。
・DACアナログ出力が0 Vになることや、I²S停止・再開時の波形品質を保証するものではありません。
・診断ビルド（USB_BRINGUP_LEVEL=3）では起動直後に診断画面を表示し、
  再生画面とFFT処理を停止します。ただし音声再生は継続します。
